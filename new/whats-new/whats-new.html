1. Introduction

Niord (Nautical Information Directory) is a system for producing and publishing Navigational Warnings (NW) and Notices to Mariners (NM). The Danish Emergency Management Agency is the organisation behind Niord.

Niord has been rebuilt. The administration application that editors, administrators and system administrators work in has been written anew, the public site where mariners read the warnings and notices has been replaced, and the server behind both has been rebuilt as well. Most of what you did in the old Niord you can still do, in the same order and with the same words, but many screens look different, some functions have moved, a few are new and a few are gone.

This guide is for you if you used the old Niord, the application the earlier user manuals describe, and now open the new one. It lists what you will notice, and for each change it says what it was, what it is now and where to find it. It does not repeat the manuals: each change links to the chapter of the editor manual, administrator manual or system administrator manual that describes it in full.

1.1. How This Guide Is Organised

The chapters follow the roles a user can hold, and within a chapter the changes are grouped by task:

  • For everyone: the layout, signing in, domains, languages, help and links.

  • For editors: finding messages, writing and publishing them, positions, the firing schedule and publications seen from a message.

  • For administrators: the Admin area, base data, users, mailing lists and the new publications model.

  • For system administrators: the Sysadmin area, where templates and texts come from, imports, batch jobs, settings and integration.

  • For mariners using the public site: the new public site.

The chapters about the administration application each end with a table of what is gone and what to use instead. A user with a higher role should read the chapters of the lower roles too: an administrator is usually also an editor.

1.2. The Base Product and the Countries

Niord is now one base product that every deployment shares. A country builds its own deployment on the base product and adds what only it needs: its domains, its languages, its texts and branding, and sometimes pages of its own. The deployments in Denmark and in Greenland are each such a country. This guide describes the base product. If your deployment shows a page or a field that this guide does not mention, it most likely belongs to your country’s additions.

1.3. The Technology in Brief

You need nothing but a current web browser. The administration application and the public site are web applications built with Angular. The server is a Spring Boot application that keeps its data in a PostgreSQL database, with PostGIS for positions and areas, and signing in is handled by Keycloak.

2. For Everyone

These changes meet every user of the administration application, whatever their role, and most of them meet a visitor who has not signed in as well.

2.1. Finding Your Way Around

2.1.1. The header and the main menu

The old application had a main menu bar with the pages as links. The new header has the Niord logo (a link to the home page), the menu items Messages, Editor, Schedule, Admin and Sysadmin, and to the right of them Help, the domain menu, your account menu and the language menu. Messages is always there; each of the other items appears only when your role in the current domain allows you to open the page behind it, and Schedule only in a domain that has a firing schedule. See Home in the editor manual.

2.1.2. Narrow screens

On a narrow window or a tablet, the menu items fold into one menu button that opens a single list of everything the header holds. The domain menu stays visible beside that button, because it tells you which data you are working on.

2.1.3. The home page

The home page is a map of the published messages that fills the window, with a small welcome panel on top of it. When you have not signed in, the panel has a Login button. See Home in the editor manual.

2.1.4. Help

The Help item in the header opens the section of the user manual that describes the page you are on. Many dialogs have a help link of their own, which opens the section about that dialog. The address of the manuals is a setting a system administrator can change, so a deployment can point the help at its own copy of the guides.

2.1.5. A badge on a test deployment

A deployment that is not the production system shows a red badge under the logo, for example TEST. It is there so that nobody mistakes test data for the real warnings and notices. A production deployment shows no badge.

2.2. Signing In and Out

2.2.1. The login page

Login takes you to the login page of the sign-in service, Keycloak, and back again once you have signed in. How you sign in, with a password or through your organisation’s own login, is set up for each deployment, so the old manual’s description of one organisation’s login no longer applies in general. See Home in the editor manual.

2.2.2. Your account and password

On a wide window, the account control in the header is a button with an icon and no text. Before you sign in it is the Login button; once you have signed in it shows a person icon, and pointing at it shows your name. Its menu has Edit <your name>, which opens your account pages in the sign-in service, where you change your password and profile, and Logout. On a narrow window, Edit <your name> and Logout (or Login, before you sign in) are entries in the list of the menu button.

2.2.3. Browsing without signing in

You can open the Messages page without signing in and read the published messages, in all its views, but you cannot change anything. Pages for editors, administrators and system administrators ask you to sign in first.

2.2.4. When your session expires

If your session expires, or the sign-in service cannot be reached, the application does not reload or log you out. Instead it carries on as if you had not signed in and shows a strip under the header, for example Your session has expired — you’re browsing as a guest., with a Login button. That button takes you to the sign-in service and back to the same address, but it loads the application afresh: your message selection is emptied, and if the editor holds changes you have not saved, the browser first asks whether to leave the page. Signing in or out from the header does the same.

2.3. Domains and Languages

2.3.1. Switching domain reloads the page

You still work in a current domain, chosen in the domain menu, where a pencil marks the domains you can edit and an eye those you can only view. What is new is that choosing another domain loads the application afresh, at the same address in most cases. A page that shows a single publication or one of its issues belongs to the domain that owns it, so from there you land on the Publications list instead. Your message selection is emptied. If the editor holds changes you have not saved, the browser first asks whether to leave the page, and the changes are discarded if you go on, so save your work before you switch.

2.3.2. What the browser remembers

The browser remembers your domain and your language until you change them, as before. The old manual said they were kept in cookies; the new application keeps them in the browser’s local storage, which you clear in the same place as cookies. A link that ends in ?domain= followed by a domain’s id opens the application in that domain.

2.3.3. Languages

The languages in the language menu are set up for each deployment. The base product itself comes with English only; a country adds its own languages. Some labels can be reworded by a system administrator in the dictionaries without a new version of the application.

2.4. When Niord Is Updated

2.4.1. The update banner

The old application kept a copy of itself in the browser, and after an update it showed an out-of-date warning on the home page, which you cleared by emptying the browser’s cache. The new application notices by itself when a newer version has been installed and shows a banner under the header, Please refresh web-browser, on whatever page you are on. Click Retry in the banner to load the new version; there is no cache to clear.

2.5. Links to Messages

2.5.1. Links that open a message

A message has an address of its own, which you can copy from the browser and send to someone: it opens the Messages page with that message shown. Links in older mails and posts, written in the old form with #/message/ in them, still open the message.

2.5.2. Opening a message in a new tab

The rows of the message lists are real links. A middle-click, or a click with Ctrl held, opens the message in a new browser tab, while a plain click opens it in the current one.

2.6. Gone, and What to Use Instead

Gone Use instead

The out-of-date warning on the home page, and clearing the browser’s cache after an update

The update banner: click Retry. See The update banner.

A selection of messages that lasted for the whole browser session

The selection now lasts until the page is reloaded, the domain is switched, or you sign in or out. Print, mail or tag the selection before you do any of these. See Selecting messages with the star.

3. For Editors

These changes meet editors in their daily work. Most of them also meet a user with the User role, who reads and comments on messages without editing them.

3.1. Finding Messages

3.1.1. Five views, with Selection as one of them

The Messages page had four view modes, Table, Grid, Details and Map, and the selected messages on a sub-page of their own. Now Selection is a fifth tab beside the four views, with a badge that counts the selected messages and a cross that clears the selection. Switching between the tabs keeps your filter. See Messages in the editor manual.

3.1.2. Selecting messages with the star

You select and deselect a message with its star, in the lists and in the message details. The selection is kept while you search, filter and change view, but it is emptied when you reload the page, switch domain, or sign in or out; the old application kept it for the whole browser session. Select all in the Actions menu selects the messages loaded so far, not every message the search could find.

3.1.3. Long result lists load in pages

A long search result is loaded a page at a time. A button at the bottom of the list says which messages it will fetch, out of how many, for example Load 100 - 200 of 340 messages, and adds them to the list. If loading fails, a Retry button fetches the same page again without losing what is already shown.

3.1.4. Hold E to open a message in the editor

If you hold down the E key while you click a message in the Table, Grid, Details or Selection view, the message opens straight in the editor instead of in the message details. It works only for a message you may open in the editor; any other message opens as usual. On some laptop touchpads a tap is ignored while a key is held down; a mouse click always works.

3.1.5. A red bar marks an overdue follow-up date

A message whose follow-up date has passed has a red bar along the left edge of its row in the Table, Details and Selection views. Point at the row to read Requires attention (e.g. expired/overdue warning). The rest of the row keeps its usual colours.

3.1.6. Message details open as a panel on the right

The message details used to open in a dialog. They now open in a panel on the right of the list, and the page’s address names the message, so you can copy it and send it to someone. As before, the panel has the previous and next arrows, a Back arrow after you have followed a reference, the selection star and a menu with Edit, Copy, Print and the tag actions. See Message Details in the editor manual.

3.1.7. Tags: a picker and a tag manager

The old Message Tag dialog has been split in two. Adding messages to a tag, removing them and choosing tags in the filter now happen in a small picker that opens where you click, with chips for private, domain and public tags. Creating, editing and deleting tags happens in Manage tags…, which you open from the Actions menu of the Messages page. A tag’s name cannot be changed once it is created, and only an administrator can unlock a locked tag. See Message Tags in the editor manual.

3.1.8. Who may use the actions

Update selection status… in the Actions menu, which changes the status of all the selected messages at once, was an action for administrators only. It is now open to editors. Import…​ is still for administrators. See Update Selection Status Action in the editor manual.

3.2. Writing a Message

3.2.1. The start screen: Create a message

When you open Editor in the main menu you no longer get a blank editor page with a template field. You get a start screen, Create a message, with a card for each type of message you can create in the current domain: Navigational Warning, Notice to Mariners, or both. A domain with only one type shows one card. Each card has a New blank NW (or NM) button and, where the domain uses templates, Select NW template… (or NM). Below the cards are your Recently edited drafts. See Blank Editor Page in the editor manual.

3.2.2. Templates on a page of their own

The old two dialogs for choosing and running message templates are gone. Choosing a template on the start screen, or Run template… in the Categories field of an open message, opens the page Execute templates. There you pick templates in a Select templates panel, which shows an example when you point at a template, fill in the Base fields and the Template parameters, and watch a preview of the result as you type. Execute replaces the whole message and opens it, unsaved, for editing. See Message Template Execution in the editor manual.

3.2.3. Save, Clear and Back sit in the header

The old editor marked unsaved changes with a red save icon beside its title and had Save Message and Reload Message buttons at the bottom of the page. The header of the editor now holds Back, which returns to the message list with your filter, a reload button, the title, a status chip that reads Unsaved changes or All changes saved, Clear and Save. Because it is the header, you can save from any of the editor’s tabs. See Editor in the editor manual.

3.2.4. Leaving with unsaved changes

If you leave the editor, or open another message in it, while you have unsaved changes, you are asked first whether to leave without saving. Saving a Verified message asks for confirmation too, because saving it returns it to Draft. The Status, Comments and History tabs appear once the message has been saved for the first time.

3.2.5. A live preview beside the fields

To the right of the fields, a Live preview shows the message as it will look, and changes as you type. Clicking a part of the preview opens the field it comes from. On a narrow window the preview is a panel you open with the Preview button in the header. See Editor in the editor manual.

3.2.6. The status steps above the preview

Above the preview, a row of steps shows where the message is: Draft, Verified, Published and, at the end, Expired or Cancelled. The steps only show the status; for an editor, a button beside them moves the message on: Verify on a Draft message and Publish on a Verified one. A Verified message with a Publish from date shows the date it is scheduled to be published instead of the Publish button. The one step you can click is Draft on a Verified message, which reverts the message to draft. Deleting, cancelling and copying stay on the Status page.

3.2.7. Manage optional fields

Which fields the editor shows is still decided by the deployment, by the message’s series, areas and categories. To show a field that is hidden, use Manage optional fields… on the Edit page, which replaces the old More Fields actions at the bottom of the Action menu. Expand all fields and Collapse all fields are in the editor’s Actions menu.

3.2.8. Two new part types

A message part could be of the type Details, Time, Positions or Note. Two types have been added, Prohibition and Signals, and like the others they decide which fields a part shows. Parts can now be reordered by dragging them by their grip, as well as with the arrow buttons. See Editor in the editor manual.

3.2.9. Citing a publication

The Publication field of a message still writes a reference to a publication into the message’s text. With the new publications model, the dialog that inserts it offers the published issues of the series that may be cited, rather than a list of publications. See Publications for what series and issues are.

3.3. Verifying, Publishing and Copying

3.3.1. The Status page

The Status page shows the message as it will be published. A row of buttons above it, one for each of the deployment’s message languages, switches the language of the preview; it starts at the language the application is shown in. Its buttons are disabled while the message has unsaved changes, so save first. A Verified message with a Publish from date shows the date it is scheduled to be published instead of a Publish button. See Status Editor Page in the editor manual.

3.3.2. Copying and cancelling ask first

Copy Message used to open the copy in the editor at once. Copy message… now opens a dialog, Copy Message?, where a copy of a Notice to Mariners can be given a reference to the message it was copied from with Include reference to copied message. Cancel message… opens a dialog too, and for a Notice to Mariners its Create cancellation message starts a new message that announces the cancellation.

3.3.3. Which publications a message is in

The Status page has a new Publications panel. It lists each publication series the message appears in, with the number of issues, and marks whether the message is Published in it, Withdrawn from it or Pending, which means it would be in the issue being prepared but can still change before that issue is published.

3.4. Positions

3.4.1. New drawing tools, Undo and Redo

The position editor opens in a large window over the editor. Its tools are now Point, Line, Area, Box, Select, Delete and Measure, and it has Undo and Redo. Its Actions menu offers Merge geometries, Split geometries and Convert to a line, an area or points. See Position Editor in the editor manual.

3.4.2. Positions from a file, or as text

You can drop a GeoJSON, KML or WKT file on the map to add its positions. The import dialog still offers From Area, From Text and From UTM. Edit as text, in the Positions field and in the position editor, lets you type or paste the positions instead of drawing them.

3.5. The Firing Area Schedule

3.5.1. Schedule is an item in the main menu

The firing schedule was a Schedule sub-page of the domain that holds the firing areas. It is now the Schedule item in the main menu, shown to editors in a domain that has a firing schedule, and opens the page Firing Area Schedule. You pick a day, edit each firing area’s periods in the list, and see the areas on a map. See Maintain Firing Exercise Schedule in the system administrator manual.

3.5.2. How often the firing exercises are updated

Update Firing Exercises… still updates the firing exercise messages from the schedule at once. The system also updates them on its own every hour, so a change to the schedule reaches the messages within the hour even if you do not press the button.

3.6. Gone, and What to Use Instead

Gone Use instead

The Selection sub-page

The Selection tab of the Messages page. See Five views, with Selection as one of them.

The Message Tag dialog

The tag picker, and Manage tags… in the Actions menu. See Tags: a picker and a tag manager.

The blank editor page with its template field

The start screen, Create a message. See The start screen: Create a message.

The Template Selection and Template Execution dialogs

The Execute templates page. See Templates on a page of their own.

The red save icon, and the Save Message and Reload Message buttons at the bottom of the page

The editor’s header: the status chip, Save and the reload button. See Save, Clear and Back sit in the header.

The More Fields actions in the Action menu

Manage optional fields… on the Edit page. See Manage optional fields.

Subtract Geometries in the position editor

No direct replacement. Draw the remaining area as it should be, or import it from a file.

Adding the selected messages to a publication, or removing them, from the message list or the editor’s menu

A publication now finds its messages by its own criteria. An administrator adds or leaves out a single message by hand on the issue. See Publications.

A message tag for each issue of a publication, such as a weekly Notices to Mariners

Filter the message list with the Publication filter, which picks an issue. Tags made by the old publications stay as they were.

4. For Administrators

These changes meet users with the Admin role, who look after the base data that editors depend on: charts, areas, sources, publications, users and mailing lists.

4.1. The Admin Area

4.1.1. A list of sections instead of one page of tiles

The old Admin page showed the base data as tiles on one page. The Admin area now has a list of its sections down the left side and an Overview page with a card for each: Charts, Areas, Publications, Publication categories, Sources, Users & Contacts and Mailing Lists. The list stays on screen, so you move between sections in one click. See Admin Page in the administrator manual.

4.1.2. Access follows the current domain

As before, you reach the Admin area when you hold the Admin role in the domain you are working in. The new application checks this against the current domain only, so switching to a domain where you are not an administrator takes the Admin item out of the menu.

4.1.3. Editing in a side panel

Charts, sources, users, mailing lists and the other lists are edited in a panel that slides in from the right over the list, instead of on a page of their own. If you close the panel with unsaved changes, you are asked first. Lists are filtered by typing in the box above them and show 20 rows to a page.

4.1.4. Seeing the data in another language

Areas, Sources and Publication categories have a Model language choice above the list. It shows the names in another of the deployment’s message languages, without changing the language of the application.

4.2. Charts, Areas and Sources

4.2.1. Charts

A chart number can no longer be changed once the chart is created. The map beside the list shows the coverage of the charts on the current page, each labelled with its number. A chart’s coverage can be drawn on the map or, with Edit as text, typed or pasted as text. See Charts in the administrator manual.

4.2.2. New actions in the Areas menu

The cog menu of the Areas page has two new actions for re-indexing, and a third, for firing areas, that is described in the next section. Re-index areas recomputes the order of the area tree. Re-index published messages recomputes the order of every published message of the current domain within its area. It overwrites any order editors have set by hand, in every area: a message in an area that sorts its messages by position is placed by its position, and every other message, including one that has no position, is reset to the same neutral value, so the order among those messages is lost. See Areas in the administrator manual.

4.2.3. Generating the firing area messages

Generate firing area messages…, in the same cog menu, creates a message for each firing area. It asks for the message series to use and, if you like, a tag to put the messages in, and it is shown only in a domain that has a firing schedule. The old manuals described this function on a country’s own integration page; it is now part of the base product.

4.2.4. Area extents as text

Like a chart’s coverage, an area’s extent can now be typed or pasted as text with Edit as text, or imported, as well as drawn.

4.3. Users and Contacts

4.3.1. Who sees the Users tab

The Users tab of Users & Contacts is shown only to an administrator who also holds the manage-users role of the sign-in service, Keycloak. Without that role you see the Contacts tab only. The Keycloak… link above the list opens the sign-in service’s own administration pages, where a user can be renamed. See Users & Contacts in the administrator manual.

4.3.2. Deleting a user

The old manual said a user could be deleted only if the user had never created or edited a message or a comment. Delete now removes the user’s account from the sign-in service at once, whatever the user has done in Niord. To keep the account but take away the access, remove the user from the user groups instead.

4.3.3. Creating a user

First and last name are separate fields, and the user name cannot be changed once the user is created. The password field is never filled in: leave it empty to keep the password. The Required actions Update Profile, Update Password and Verify Email are sent only when the user is created.

4.4. Mailing Lists

4.4.1. One page for both administrators and system administrators

Mailing Lists is still a section of the Admin area. An administrator manages the recipients of each list, and a system administrator also creates, edits, copies and deletes lists and their triggers on the same page. A list is edited in a side panel where each trigger is a card you can fold away. See Mailing Lists in the administrator manual and Mailing Lists in the system administrator manual.

4.4.2. Recipients

Users and contacts are added to a list in two separate parts of the recipients panel, and each part has its own Save. The buttons that add or remove all recipients act only on the rows your filter shows.

4.4.3. Triggers

A scheduled trigger cannot be saved without a time zone. Test runs a trigger as it stands in the panel, before you save it, so you can try a change first.

4.5. Publications

Publications have changed more than anything else in Niord. The old model of publication templates, publications, file types, message tag filters and a Recording status has been replaced by series and issues. The screens for publications are still being finished, so this section describes the model only in outline; see Publications in the administrator manual for the screens.

4.5.1. Series, issues, one-off publications and categories

A series is a publication as a standing thing, for example a weekly Notices to Mariners. It holds the settings that all its issues follow: its category, how often it comes out, how its content is made, which messages it selects and how its files are named. An issue is one released document of a series, for example the Notices to Mariners of one week. A one-off publication is a publication that comes out once, such as a single uploaded document or a link to one. A category groups publications, and decides whether they are shown on the public site.

Category  "Notices to Mariners"     (shown on the public site, or not)
 |
 +-- Series  "Weekly Notices to Mariners"
 |     +-- Issue  week 26    published
 |     +-- Issue  week 27    published
 |     +-- Issue  week 28    open: being prepared
 |
 +-- One-off publication  "List of firing areas"
       +-- its single issue

4.5.2. How a series gets its content

A series' content is Generated from criteria, an Uploaded PDF, an External link or Reference only. A generated series chooses its messages by criteria, such as message series, areas and categories, instead of the old message tag filter. It also says how a message belongs to an issue: Published in the issue’s interval, In force at the cut-off, or Compiled from another series, which builds, for example, a yearly list from the weekly issues.

4.5.3. Preparing and publishing an issue

An issue is prepared while it is open: it shows which messages it will hold and which the criteria leave out, and why. Before you publish it, a Checklist shows what is ready and what needs your attention. When you publish it, its list of messages is frozen and its document is made; in a series that comes out regularly, the next issue then opens by itself. A published issue can be amended, given a new edition or withdrawn from the public site, and every change is kept in its history.

4.5.4. Adding or leaving out a message by hand

On an open issue, a message can be added by hand or left out of the issue, always with a reason that is kept in the history. An administrator may do this from the issue’s page in the Admin area. The server also accepts a separate role for it, publication-curate, but because the pages for publications are in the Admin area, that role on its own gives no page to work from; see A new role for publications.

4.5.5. Publications belong to a domain

The Publications page lists the series and one-off publications of the current domain only, and a publication can be changed only from the domain that owns it. A setting on each publication decides from which domains its issues can be cited in a message.

4.5.6. Publication categories have a section of their own

Publication categories were a tab of the old Publications page. They are now the section Publication categories, with the fields Category ID, Name, Description, Show on the public site and Order, and a column that counts the publications in each. A category cannot be deleted while a series or a publication belongs to it. See Publication Categories in the administrator manual.

4.6. Gone, and What to Use Instead

Gone Use instead

The Admin page with tiles

The Admin area’s list of sections and its Overview page. See A list of sections instead of one page of tiles.

Publication templates

A series: it holds the settings every issue follows. See Series, issues, one-off publications and categories.

The file types None, Link, Uploaded File and Message of a publication

A series' content: Reference only, External link, Uploaded PDF or Generated from criteria. See How a series gets its content.

The Message Tag Filter of a publication

The criteria of a series. See How a series gets its content.

The Recording status and Release Publication…​

An open issue, and publishing it after the checklist. See Preparing and publishing an issue.

The Publication Categories tab of the Publications page

The Publication categories section. See Publication categories have a section of their own.

Deleting a user only when the user has no history

Delete removes the account at once; to keep it, remove the user from the groups. See Deleting a user.

Importing charts, areas or sources by copying a file into a folder on the server

Import…​ in the cog menu of the section. See No more folders that start an import.

5. For System Administrators

These changes meet users with the Sysadmin role, who set up and configure Niord. The biggest one is not a screen but a rule: a deployment’s data is changed only by the people who run it. A new version of Niord may add texts and settings the deployment never had, but it never changes or deletes what is there.

5.1. The Sysadmin Area

5.1.1. A list of sections and an overview

Like the Admin area, the Sysadmin area has its sections down the left side and an Overview page with a card for each. The Sysadmin role counts in the domain you are working in, so switching to a domain where you do not hold it takes the area out of the menu. See Sysadmin Page in the system administrator manual.

5.1.2. Copy, and editing in a side panel

Most lists are edited in a side panel instead of on an edit page. Message series, domains, dictionary entries, parameter types, script resources and mailing lists have a Copy action, which opens a new record filled in from the one you copied.

5.2. Where Templates, Texts and Reports Come From

5.2.1. The database is the only source

In the old Niord, templates and standard texts came with the application and could be loaded again from it with a reload. Now every template, script, text and report is read from the database and nowhere else. Templates, scripts and reports arrive once, when a new deployment is set up, and after that only when a system administrator imports them. Texts and settings are added at start-up instead: a new version of Niord can bring new text keys and new settings, which are added the first time it starts. A new version never changes or deletes what a deployment holds, and it never adds again a text or a setting that an operator deleted. Something an operator deleted stays deleted until somebody imports it again. See Script Resources in the system administrator manual.

5.2.2. New templates arrive as files to import

When a new version of Niord brings a new or changed template, it comes as a release file that a system administrator imports on the Script Resources page. Nothing reaches a running deployment until it is imported. A list of template paths that the data names but the database lacks, the missing-path report, is written to the server log at start-up and marks those paths in the import.

5.2.3. Imports show what they would change

The imports of Script Resources and Dictionaries now show what the file would do before anything is written: what it would add, what it would overwrite, what is unchanged and what it refuses, with the reason. New entries are ticked and changed ones are not; for a changed script you see the two versions side by side. Only what you tick is imported. See Dictionaries in the system administrator manual.

5.2.4. Deleting a dictionary entry

Before you delete a dictionary entry, the confirmation lists what uses it: parameter types, scripts and the parts of Niord that read it. An entry that a parameter type lists cannot be deleted. An entry that you delete stays deleted after a restart; to restore it, import it again, and the import offers it unticked as Deleted by an operator.

5.2.5. The built-in print reports

The old manual said that Niord always ensures two standard reports. A new deployment now gets three built-in reports when it is set up, standard, draft and public, the last one used by the public site’s print. Niord does not create them again, so a report you delete stays deleted until you import it again on the Print Reports page. See Print Reports in the system administrator manual.

5.3. Batch Jobs and Imports

5.3.1. No more folders that start an import

The old manuals said that an import could be started by copying a file into a folder under $NIORD_HOME/batch-jobs/. No folder on the server starts a job any more. Every import is started from its page, with Import…​ in the cog menu, or from the Batch Jobs page. See Batch Jobs in the system administrator manual.

5.3.2. Batch sets

A batch set, a zip file that starts several imports at once, is uploaded on the Batch Jobs page. A set that names the script resource, dictionary or settings import, or the JavaScript job, is refused whole and starts nothing; those run from their own pages.

5.3.3. Execute JavaScript

The Batch Jobs page has Execute JavaScript, which runs a script on the server as a batch job, with full access to the system. It asks for confirmation first, and the script’s output appears only in that job’s log files.

5.3.4. The jobs that set up a deployment

The jobs that loaded a new deployment’s first data are listed on the Batch Jobs page like any other job, but they cannot be restarted from there. The first set of data is loaded once; if that fails, the deployment is set up again on an empty database.

5.4. Configuration

5.4.1. Settings

The Settings page lists only the settings that Niord’s code declares as editable; values the system keeps for itself, such as the time the areas were last changed, are not listed. A setting row left over from an older version, which no code reads, stays in the database but is neither listed nor exported. A few settings worth knowing: documentationUrl decides where every Help link goes, adminIntegrationPageEnabled shows the Niord Integration page, and mailValidRecipients decides whether mails are really sent. See Settings in the system administrator manual.

5.4.2. Message series

A series has a new field, Exclude messages from free-text search index. An Insert menu beside the short format lists the tokens you can use, among them ${week}, ${week-2-digits} and, for an NM series, ${t-or-p}. The next number is changed in a small window with Compute and Update, and series have no import or export. See Message Series in the system administrator manual.

5.4.3. Domains

A domain must have a time zone; it cannot be saved without one, because every date in that domain is shown in it. A domain’s client in the sign-in service is still created with the domain, and if that failed, the domain’s panel shows it and offers Create in Keycloak. See Domains in the system administrator manual.

5.4.4. Promulgation types

Audio is now part of the base product, not of one country’s version, and a new deployment starts with the promulgation types NAVTEX, Twitter and Audio. A type’s own settings, such as the NAVTEX transmitters, can be edited once the type has been saved. See Promulgation Types in the system administrator manual.

5.4.5. Categories and templates

A template category has a Test… button that runs the template on its example message and shows the result in each language. The cog menu has Re-index categories, which recomputes the order of the whole category tree. See Categories in the system administrator manual.

5.4.6. Firing schedules

The Firing Schedules page still configures the generator of firing exercise messages. The generator runs every hour, and Update firing exercises…​ in the page’s cog menu runs it at once. Editors maintain the schedule itself from the Schedule item in the main menu, and the firing area messages are generated from the Areas page. See Firing Schedules in the system administrator manual.

5.4.7. A new role for publications

Besides user, editor, admin and sysadmin, the server knows a new client role, publication-curate, which allows a user to add a message to a publication issue by hand or leave one out. An administrator may do the same without it. Two things limit the role for now. Niord does not create it: when Niord creates a domain’s client in the sign-in service, together with the domain or with Create in Keycloak on the Domains page, the client gets only user, editor, admin and sysadmin, so the role exists only where the realm’s set-up file has it or a system administrator has added it to the client by hand. And the pages for publications are in the Admin area, which needs the admin or sysadmin role, so a user who holds only publication-curate has no page to work from. A role counts only when it is held as a client role for the domain; a realm role with the same name gives nothing.

5.5. Integration With Other Systems

5.5.1. The Niord Integration page

The old Integration chapter described import panels that belonged to one country’s deployment. The base product has the page Niord Integration instead, which pulls the published messages of chosen message series from another Niord server into series of this one, about once an hour, and on demand from the row’s action. It is shown only when the setting adminIntegrationPageEnabled is on. A country may add integration pages of its own. See Integration in the system administrator manual.

5.6. Gone, and What to Use Instead

Gone Use instead

Reloading script resources and standard dictionaries from the application

Import the release file or the texts file, with the preview. See Imports show what they would change.

Copying a file into a batch-jobs folder on the server to start an import

Import…​ on the section’s page, or a batch set on the Batch Jobs page. See No more folders that start an import.

Standard reports that Niord re-created by itself

The built-in reports come once with a new deployment; import them again if they were deleted. See The built-in print reports.

Settings rows that no code reads, on the Settings page

Nothing: they are kept in the database but no longer shown. See Settings.

The import panels of the old Integration chapter

Niord Integration for another Niord server; a country’s own pages for anything else. See The Niord Integration page.

The AtoN module page

The new application has no AtoN page. A domain’s AtoNs flag and a category’s AtoN filter are kept with the data.

6. For Mariners Using the Public Site

The public site is where mariners and anyone else read the Navigational Warnings and Notices to Mariners without signing in. It has been replaced by a new site. It shows the same messages, but it looks different, and a few things work differently. The base product’s site is in English; a country’s site adds its own languages, which you choose with the language buttons in the menu bar.

6.1. Reading the Messages

6.1.1. Details, List and Map

The menu bar has three views of the messages. Details, where the site opens, shows the full text of every message under the heading of its area. List shows one line for each message, with its number and title. Map shows the messages on a chart, and lists the messages that have no position in a panel called Additional Messages.

6.1.2. Choosing what is shown

Above the messages, Navigational Warnings and Notices to Mariners switch each kind of message on or off; one of them is always on. Show Active Now limits the list to the messages in force at this moment. Print opens the messages you are looking at as a PDF document, ready to print or save.

6.1.3. One message, and links to it

Clicking a message in the List or on the Map opens it in a window with its map, its full text, arrows to the previous and next message, and a button that prints that message alone. A single message also has an address of its own, /messages/details/message/ followed by its id, which you can bookmark or send to someone.

6.1.4. Addresses without the "#"

The addresses of the old public site had a # in them, for example /#/messages/map. The new site’s addresses have none: the map is simply /messages/map. Bookmarks and links written for the old site still work, because the new site turns them into the new form when it opens.

6.2. Publications

6.2.1. The Downloads page

Downloads in the menu bar lists the publications, such as the weekly Notices to Mariners, grouped by category. Its first tab, Active NtM and Publications, holds the publications that are current now. The second, Historical NtM and Publications, holds older ones: choose a period under Date Interval to see what was published in it.

6.2.2. Download or browse an issue

A publication with a document has a Download link, which opens it. A publication made from messages also has Browse, which shows the messages of that issue on the Details view of the site, so you can read them there instead of in the document.

6.2.3. Why a publication is or is not listed

A publication is listed when three things are all true: its category is one the site shows, it has not been withdrawn, and the period in which it is public has begun. A withdrawn publication disappears from the site, from the historical tab as well, but messages that cite it still show the reference.

6.3. For Sites That Show the Messages

6.3.1. The teaser for other web sites

Another web site can show a small map of the current messages, the teaser, which leads to the public site when it is clicked. Its address is /teaser, and it accepts area to limit it to one area and lang to choose the language. A teaser address written in the old form, with #? before these parameters, still works.

6.3.2. On a phone

The site works on a phone. On a narrow screen the menu bar shows its icons without their labels, and the panel of messages without a position can be made smaller so that it leaves the map free.
